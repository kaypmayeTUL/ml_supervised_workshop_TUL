Understanding Machine Learning Methods

What is Machine Learning?

Machine Learning is teaching computers to learn patterns from data and make predictions or decisions without being explicitly programmed for every scenario.

Think of it like teaching someone to recognize cats:

  • Instead of writing rules ("has whiskers, pointy ears, says meow"), you show them many examples
  • They learn the patterns that distinguish cats from other animals
  • Eventually, they can recognize new cats they've never seen before

Types of Machine Learning

🎯 Supervised Learning

Learning from labeled examples

You have data with known answers (labels), and the algorithm learns to predict those answers for new data.

Examples: Predicting house prices, spam detection, medical diagnosis

🔍 Unsupervised Learning

Finding hidden patterns

Data has no labels; the algorithm discovers structure and patterns on its own.

Examples: Customer segmentation, anomaly detection, recommendation systems

🎮 Reinforcement Learning

Learning through trial and error

The algorithm learns by taking actions and receiving rewards or penalties.

Examples: Game-playing AI, robotics, self-driving cars

Today's Focus: Supervised Learning

In this workshop, we're using Supervised Learning to predict car prices. We have:

  • Input features: Car age, mileage, brand, fuel type
  • Target variable: Price (what we want to predict)
  • Training data: Historical data with known prices

📚 Key Terms

  • Feature (X): An input variable used to make predictions (e.g., car age, mileage). Think of features as the "questions" you ask about your data.
  • Target (y): The value you're trying to predict (e.g., car price). Also called the "label" or "outcome."
  • Sample: A single row in your dataset representing one observation (e.g., one car with all its details).

✅ Our Goal: Train a model that can accurately predict the price of any car based on its characteristics.

⚖️ Overfitting vs. Underfitting

One of the most important concepts in machine learning is finding the right balance between a model that's too simple and one that's too complex.

📉 Underfitting

The model is too simple

Like studying only chapter 1 for a 10-chapter exam. The model hasn't learned enough patterns from the data.

Signs:

  • Poor performance on training data
  • Poor performance on test data
  • Model misses obvious patterns

Fix: Use a more complex model, add more features, train longer

📈 Overfitting

The model is too complex

Like memorizing answers instead of understanding concepts. The model learned the training data too well, including noise and outliers.

Signs:

  • Excellent performance on training data
  • Poor performance on test data
  • Model doesn't generalize

Fix: Use simpler model, get more data, use regularization

🎯 The Goal: Generalization

We want our model to learn the underlying patterns in the data, not memorize specific examples. A well-generalized model performs well on data it has never seen before. This is why we split data into training and testing sets!

With so many algorithms available, how do you know which one to use? Start by asking: What type of problem am I solving?

📈 Regression

Ask yourself: "How much?" or "How many?"

Algorithms: Linear Regression, Random Forest

🏷️ Classification

Ask yourself: "Which category?" or "Yes or No?"

Use when predicting a discrete category.

Examples: Spam detection, disease diagnosis

Algorithms: Logistic Regression, Decision Trees

🔍 Clustering

Ask yourself: "What groups exist in my data?"

Use when you have no labels and want to find structure.

We're creating a synthetic dataset (fake but realistic data) of 500 used cars. This simulates what you might see in real car sales data. We generate random values for:

# Set random seed np.random.seed(42) # Number of samples n_samples = 500 # Generate features car_data = { 'brand': np.random.choice(['Toyota', 'Honda', 'Ford', 'BMW', 'Mercedes', 'Audi', 'Chevrolet', 'Nissan'], n_samples), 'age_years': np.random.randint(0, 15, n_samples), 'mileage_km': np.random.randint(5000, 200000, n_samples), 'engine_size_L': np.random.choice([1.4, 1.6, 1.8, 2.0, 2.5, 3.0, 3.5], n_samples), 'fuel_type': np.random.choice(['Petrol', 'Diesel', 'Hybrid', 'Electric'], n_samples, p=[0.5, 0.3, 0.15, 0.05]), 'transmission': np.random.choice(['Manual', 'Automatic'], n_samples, p=[0.4, 0.6]), 'num_owners': np.random.randint(1, 5, n_samples), 'accident_history': np.random.choice(['No', 'Yes'], n_samples, p=[0.7, 0.3]) } # Create DataFrame df = pd.DataFrame(car_data) # Calculate price based on features (with some realistic relationships) brand_multiplier = {'Toyota': 1.0, 'Honda': 1.05, 'Ford': 0.95, 'BMW': 1.4, 'Mercedes': 1.5, 'Audi': 1.35, 'Chevrolet': 0.9, 'Nissan': 0.95} fuel_multiplier = {'Petrol': 1.0, 'Diesel': 1.05, 'Hybrid': 1.2, 'Electric': 1.3} transmission_multiplier = {'Manual': 0.95, 'Automatic': 1.05} accident_multiplier = {'No': 1.0, 'Yes': 0.85} base_price = 25000 df['price'] = ( base_price * df['brand'].map(brand_multiplier) * (1 - df['age_years'] * 0.06) * # Depreciation (1 - df['mileage_km'] / 500000) * # Mileage impact (1 + df['engine_size_L'] * 0.08) * # Engine size premium df['fuel_type'].map(fuel_multiplier) * df['transmission'].map(transmission_multiplier) * (1 - (df['num_owners'] - 1) * 0.05) * # Multiple owners penalty df['accident_history'].map(accident_multiplier) ) # Add some random noise to make it realistic df['price'] = df['price'] * np.random.uniform(0.9, 1.1, n_samples) df['price'] = df['price'].round(2) # Ensure no negative prices df['price'] = df['price'].clip(lower=3000) print(f"Dataset created with {len(df)} cars! 🎉") print(f"\nFirst few rows:") df.head(10)

📚 Key Terms: Training vs. Testing

We split our data into two sets:
  • Training Set (80%): The data used to teach the model. The model learns patterns from this data by adjusting its internal settings.
  • Testing Set (20%): Data the model has never seen. We use this to evaluate how well the model performs on new, unseen examples.

Why split? If we tested on the same data we trained on, we wouldn't know if the model actually learned useful patterns or just memorized the answers!

📏 Feature Scaling: Why It Matters

Before training models, we often need to scale our features. But why?

⚠️ The Problem: Features on Different Scales

Consider our car data:

  • Age: 0-15 years (small numbers)
  • Mileage: 5,000-200,000 km (large numbers)
  • Engine Size: 1.4-3.5 L (tiny numbers)

Without scaling, algorithms might think mileage is more important just because it has bigger numbers!

Common Scaling Methods

📊 Standardization (Z-score)

Formula: z = (x - mean) / std

Centers data around 0 with standard deviation of 1.

Use when: Data has outliers, or algorithm assumes normal distribution

Result: Values typically between -3 and +3

from sklearn.preprocessing import StandardScaler
scaler = StandardScaler()
X_scaled = scaler.fit_transform(X)

📐 Normalization (Min-Max)

Formula: x' = (x - min) / (max - min)

Scales all values to a fixed range, usually 0-1.

Use when: You need bounded values, or for neural networks

Result: Values between 0 and 1

from sklearn.preprocessing import MinMaxScaler
scaler = MinMaxScaler()
X_scaled = scaler.fit_transform(X)

🧮 Understanding the Models: Math & Intuition

Before we build our models, let's understand how they work under the hood. We'll use two different approaches to predict car prices.

📈 Model 1: Linear Regression

The Idea: Find the best straight line (or hyperplane) that fits the data.

The Math:

ŷ = β₀ + β₁x₁ + β₂x₂ + ... + βₙxₙ

Where:

  • ŷ = Predicted price
  • β₀ = Intercept (base price when all features are 0)
  • β₁, β₂, ..., βₙ = Coefficients (how much each feature affects price)
  • x₁, x₂, ..., xₙ = Feature values (age, mileage, etc.)

Example: Price = $30,000 - ($800 × Age) - ($0.05 × Mileage) + ($2,000 × Is_Luxury)

Linear regression finds the line that minimizes the distance between predictions and actual values.

🌲 Model 2: Random Forest

The Idea: Build many decision trees, each making predictions, then average their results.

How It Works:

  1. Bootstrap Sampling: Create multiple random subsets of the training data
  2. Build Trees: Train a decision tree on each subset
  3. Aggregate: Average all tree predictions (for regression) or vote (for classification)

Why Random Forest Works Better:

  • Each tree sees different data patterns (reduces overfitting)
  • Averaging reduces errors from individual trees
  • Can capture non-linear relationships that linear regression misses

⚖️ Model Comparison

Aspect Linear Regression Random Forest
Complexity Simple, fast More complex, slower
Interpretability Easy to understand coefficients Harder to interpret
Relationships Assumes linear relationships Captures non-linear patterns
Accuracy Good for linear data Often more accurate

Step 6: Evaluate Model Performance

💡 What This Code Does:

After training, we need to know: How good is our model? We use several metrics:

  • MAE (Mean Absolute Error): Average dollar amount our predictions are off by
  • RMSE (Root Mean Squared Error): Similar to MAE but penalizes large errors more
  • R² Score: Percentage of price variation explained by our model (closer to 1.0 is better)

Lower MAE/RMSE and higher R² indicate better predictions!

def evaluate_model(y_true, y_pred, model_name): """ Calculate and display regression metrics """ mae = mean_absolute_error(y_true, y_pred) mse = mean_squared_error(y_true, y_pred) rmse = np.sqrt(mse) r2 = r2_score(y_true, y_pred) print(f"\n{'='*50}") print(f"{model_name} Performance Metrics") print(f"{'='*50}") print(f"Mean Absolute Error (MAE): ${mae:,.2f}") print(f"Root Mean Squared Error (RMSE): ${rmse:,.2f}") print(f"R² Score: {r2:.4f}") print(f"{'='*50}") return {'mae': mae, 'rmse': rmse, 'r2': r2} # Evaluate both models lr_metrics = evaluate_model(y_test, y_pred_lr, "Linear Regression") rf_metrics = evaluate_model(y_test, y_pred_rf, "Random Forest")

📚 Key Terms: Evaluation Metrics

  • MAE (Mean Absolute Error): The average difference between predictions and actual values. If MAE = $2,000, your predictions are off by $2,000 on average. Lower is better.
  • RMSE (Root Mean Squared Error): Similar to MAE, but penalizes large errors more heavily. Useful when big mistakes are especially bad. Lower is better.
  • R² Score (Coefficient of Determination): The proportion of variance in the target that your model explains.
    • R² = 1.0 → Perfect predictions
    • R² = 0.8 → Model explains 80% of the variation
    • R² = 0.0 → Model is no better than just guessing the average
    Higher is better (max 1.0).
# Visualize predictions vs actual values fig, axes = plt.subplots(1, 2, figsize=(16, 6)) # Linear Regression axes[0].scatter(y_test, y_pred_lr, alpha=0.5, color='blue') axes[0].plot([y_test.min(), y_test.max()], [y_test.min(), y_test.max()], 'r--', lw=2) axes[0].set_xlabel('Actual Price ($)') axes[0].set_ylabel('Predicted Price ($)') axes[0].set_title(f'Linear Regression\nR² = {lr_metrics["r2"]:.4f}') axes[0].grid(alpha=0.3) # Random Forest axes[1].scatter(y_test, y_pred_rf, alpha=0.5, color='green') axes[1].plot([y_test.min(), y_test.max()], [y_test.min(), y_test.max()], 'r--', lw=2) axes[1].set_xlabel('Actual Price ($)') axes[1].set_ylabel('Predicted Price ($)') axes[1].set_title(f'Random Forest\nR² = {rf_metrics["r2"]:.4f}') axes[1].grid(alpha=0.3) plt.tight_layout() plt.show() print("\nThe red dashed line represents perfect predictions.") print("Points closer to this line indicate better predictions.")

⚠️ Bias in Machine Learning

Machine learning models are only as good as the data they learn from. If the training data contains biases, the model will learn and potentially amplify those biases.

🚨 What is ML Bias?

ML bias occurs when a model produces systematically unfair outcomes for certain groups of people. This isn't a bug—it's the model accurately learning patterns that exist in biased historical data.

Sources of Bias

📊 Data Collection Bias

Problem: Training data doesn't represent the real world

Example: A facial recognition system trained mostly on light-skinned faces performs poorly on darker skin tones

Fix: Collect diverse, representative data

📜 Historical Bias

Problem: Past data reflects historical discrimination

Example: A hiring model trained on past decisions learns to favor male candidates because historically men were hired more often

Fix: Audit data for historical inequities

🏷️ Label Bias

Problem: Human labelers bring their own biases

Example: Content moderation trained on labels from one cultural perspective may misclassify content from other cultures

Fix: Use diverse labeling teams, clear guidelines

🔄 Feedback Loop Bias

Problem: Model predictions influence future data

Example: Predictive policing sends more officers to certain neighborhoods, leading to more arrests there, "confirming" the prediction

Fix: Monitor for self-reinforcing patterns

Real-World Examples of ML Bias

  • Healthcare: An algorithm used by hospitals was found to systematically deprioritize Black patients for extra care, because it used healthcare costs as a proxy for health needs
  • Criminal Justice: Risk assessment tools have shown racial disparities in predicting recidivism
  • Hiring: Amazon scrapped an AI recruiting tool that showed bias against women
  • Finance: Credit scoring algorithms have been found to charge higher rates to minorities

✅ How to Address Bias

  1. Audit your data: Check for demographic representation and historical patterns
  2. Test for fairness: Evaluate model performance across different groups
  3. Include diverse perspectives: Have people from different backgrounds review your work
  4. Monitor continuously: Bias can emerge over time as populations change
  5. Be transparent: Document limitations and potential biases

🚫 When NOT to Use Machine Learning

Machine learning is powerful, but it's not always the right solution. Knowing when not to use ML is just as important as knowing how to use it.

Don't Use ML When...

📏 Simple Rules Work

If you can solve the problem with straightforward if-then rules, don't overcomplicate it.

Example: "If temperature > 100°F, show fever alert" doesn't need ML.

Better approach: Write simple business logic

📉 Not Enough Data

ML needs data to learn patterns. Too little data = unreliable models.

Rule of thumb: Need at least 10x samples per feature, often much more.

Better approach: Collect more data first, or use expert rules

🎯 100% Accuracy Required

ML models make mistakes. If errors are unacceptable, ML may not be appropriate.

Example: Safety-critical systems where any error could be fatal.

Better approach: Human oversight, deterministic systems

🔍 Explainability is Critical

Some ML models are "black boxes." If you must explain every decision, this is problematic.

Example: Legal or medical decisions requiring clear reasoning.

Better approach: Simpler, interpretable models or rule-based systems

💰 Cost Exceeds Benefit

ML requires time, expertise, compute resources, and ongoing maintenance.

Consider: Data collection, training, deployment, monitoring costs.

Better approach: Manual processes or simpler automation

⚖️ Ethical Concerns

Some applications raise serious ethical questions even if technically possible.

Examples: Surveillance, manipulation, decisions affecting vulnerable populations without oversight.

Better approach: Human judgment, democratic oversight

The Right Questions to Ask

Before starting any ML project, ask yourself:

  1. What problem am I actually solving? (Not "how can I use ML?")
  2. Do I have enough quality data? (Garbage in = garbage out)
  3. What happens when the model is wrong? (And it will be wrong sometimes)
  4. Could a simpler solution work? (Start simple, add complexity only if needed)
  5. Who could be harmed? (Consider unintended consequences)
  6. Can I maintain this long-term? (Models need monitoring and updates)

💡 The Golden Rule

Use ML when the patterns are too complex for humans to codify manually, you have sufficient quality data, the cost of errors is acceptable, and the benefits outweigh the costs.
